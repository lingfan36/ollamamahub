# Quantization Guide

## 1. 什么是量化

量化是用更低位宽表示模型权重/缓存，以降低显存与内存占用，通常会牺牲部分精度。

## 2. 常见量化等级（示意）

| 类型 | 资源占用 | 质量趋势 | 适用场景 |
|---|---|---|---|
| `Q4_0` | 低 | 中 | 本地开发、低成本部署 |
| `Q5` | 中低 | 中上 | 通用在线服务 |
| `Q8_0` | 中高 | 高 | 质量优先场景 |
| `F16` | 高 | 很高 | 研究/高配机器 |

## 3. 选择策略

1. 先确定延迟与成本预算。
2. 用同一评测集测试准确率/稳定性。
3. 优先满足业务 SLA，再追求更高质量。

## 4. 与 KV Cache 的关系

2026 常见实践会对 KV cache 也做量化（如 `q8_0`/`q4_0`）来换取更大上下文。

示例：

```bash
export OLLAMA_KV_CACHE_TYPE=q8_0
```

## 5. 验证方法

- 同 prompt 对比不同量化输出质量。
- 压测吞吐与 P95 延迟。
- 记录显存峰值与 OOM 次数。

## 6. 常见误区

- 误以为更高精度一定更好：很多业务在 Q4/Q5 已足够。
- 只看平均延迟：应关注长尾延迟和稳定性。
- 不做回归测试就切换量化：容易造成线上质量波动。
