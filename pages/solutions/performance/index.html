Performance Tuning

Optimize Ollama to achieve higher tokens per second and lower latency. Understand how to manage hardware effectively for large language models.

VRAM Management

Ollama automatically attempts to offload layers to the GPU to maximize performance. If a model is too large for your available VRAM, it will split inference between the GPU and CPU, which drastically reduces speed.

When starting Ollama, you can view the resource allocation in the logs to see how many layers were offloaded.

Selecting the Right Quantization

Quantization reduces the precision of model weights, allowing larger models to fit into smaller memory spaces with minimal performance degradation. By default, most models use 4-bit quantization (Q4_0).

  • Q2/Q3: Extremely compressed. Noticeable loss of accuracy.
  • Q4_0: The default standard. Good balance of speed and fidelity.
  • Q5/Q6: Better accuracy, larger file size. Use if you have extra VRAM.
  • Q8 / FP16: Highest precision, requires massive VRAM for large models.

Multi-GPU Configuration

If you have multiple GPUs, Ollama will spread model layers across them automatically. However, there is some overhead to transferring data across PCIe.

To restrict Ollama to specific GPUs, use the CUDA_VISIBLE_DEVICES environment variable:

export CUDA_VISIBLE_DEVICES=0,1
ollama serve

CPU Tuning

For CPU inference, Ollama typically uses a subset of your CPU threads. Too many threads can actually harm performance due to context switching overhead.

You can set the OLLAMA_NUM_PARALLEL environment variable to experiment with different thread counts.

export OLLAMA_NUM_PARALLEL=8
ollama serve
