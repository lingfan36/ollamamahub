Advanced Configurations

Learn how to maximize Ollama's performance with multi-GPU setups, advanced memory management, and containerized deployments using Docker.

GPU Acceleration

Ollama automatically detects and utilizes available GPUs to accelerate model inference. Supported backends include:

  • NVIDIA (CUDA): Most consumer and datacenter NVIDIA GPUs.
  • AMD (ROCm): Supported Radeon and Instinct GPUs.
  • Apple Silicon (Metal): Native acceleration on M1, M2, and M3 series chips.

Multi-GPU Setup

Ollama can split large models across multiple GPUs. This is handled automatically, but you can control which GPUs Ollama uses by setting environment variables.

# Linux / macOS (CUDA) - Use GPU 0 and 2
export CUDA_VISIBLE_DEVICES=0,2
ollama serve

# AMD ROCm
export HIP_VISIBLE_DEVICES=0,1
ollama serve

VRAM Management

Models are loaded into VRAM to ensure the fastest generation speeds. If a model is too large for your GPU(s), Ollama will offload layers to the CPU RAM, which is significantly slower.

Tip: You can observe how much VRAM a model requires by running ollama run <model> --verbose and checking the memory metrics.

Docker Deployment

Deploying Ollama in Docker is ideal for server environments and cloud infrastructure. The official Ollama image supports CPU and GPU execution.

CPU-only Deployment

docker run -d -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama

NVIDIA GPU Deployment

To use NVIDIA GPUs in Docker, install the NVIDIA Container Toolkit first, then run:

docker run -d --gpus=all -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama

AMD GPU Deployment

For AMD GPUs using ROCm, use the rocm image tag and pass the required devices:

docker run -d --device /dev/kfd --device /dev/dri -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama:rocm

Customizing Server Options

You can adjust how the Ollama server behaves using environment variables. When using Docker, pass these with the -e flag.

  • OLLAMA_HOST: The IP and port to bind to (e.g., 0.0.0.0:11434 for external access).
  • OLLAMA_ORIGINS: A comma-separated list of allowed origins for CORS.
  • OLLAMA_MODELS: Directory where models are stored.
  • OLLAMA_KEEP_ALIVE: Duration models stay in memory after a request (e.g., 5m).

Docker Compose Example

A typical docker-compose.yml for a robust Ollama setup:

version: '3.8'
services:
  ollama:
    image: ollama/ollama:latest
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama
    environment:
      - OLLAMA_HOST=0.0.0.0
      - OLLAMA_ORIGINS=http://localhost:3000
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]

volumes:
  ollama_data:
